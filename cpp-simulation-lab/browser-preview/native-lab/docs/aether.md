# Aether World

A working C++17 procedural 3D world and physics sandbox prototype. A bounded prompt grammar produces a floating island, connected platforms, triangle meshes, rigid AABB bodies, and a three-reservoir valve puzzle. The CLI emits geometry and simulation snapshots for a renderer to consume. The native executable is the primary implementation; a browser mirror or replay is a separate presentation layer.

## Build and run

Requires GNU Make, a C++17 compiler, and Python 3 for CLI integration tests. No third-party C++ dependencies.

```sh
make
./build/aether --seed 42 --steps 2400
./build/aether --seed 42 --steps 2400 --valve gate=on --json > replay.json
./build/aether --seed 7 --steps 1200 \
  --prompt 'floating island; platforms 6; bridges on; water off; bodies 5; wind 2' --json
./build/aether --steps 2400 --action 120:gate=on --json
make test
make sanitize
make examples
```

The same seed, spec, actions, compiler/runtime, and sample interval reproduce byte-identical output. Seeded randomness uses an explicit unsigned 32-bit LCG. Cross-platform transcendental-library differences can change the last bits of decorative rock geometry; cross-toolchain bit identity is not promised.

## Prompt contract

This is a finite scene grammar, not an LLM or text-to-code system. It accepts case-insensitive, semicolon-separated clauses, trims whitespace, and rejects unsupported clauses, duplicates, empty clauses, nonfinite values, and more than 512 input bytes or 12 clauses. No prompt or action is evaluated as code.

```ebnf
scene     = clause, { ";", clause } ;
clause    = "floating island" | "island"
          | "platforms", integer | "bodies", integer
          | "bridges", switch | "water", (switch | "puzzle")
          | "gravity", number | "wind", number ;
switch    = "on" | "off" ;
integer   = one to three decimal digits ;
number    = finite decimal or scientific-notation number ;
action    = step, ":", ("feed" | "gate"), "=", switch ;
```

Omitted clauses use defaults: 4 platforms, 3 bodies, bridges and water enabled, gravity 9.81, wind 0. The accepted spec is repaired into supported ranges: platforms and bodies 1–8, gravity 0.5–20, wind −5–5. Repairs are deterministic and exposed in `summary.validation.repairs`. Overlapping initial bodies are raised in bounded one-unit increments. Accepted scenes have at most 32 recorded repairs, with at most 16 spawn attempts per body; scenes that cannot satisfy constraints are rejected.

`--steps` is bounded to 0–100000. `--sample-every` defaults to 30 and is bounded to 1–100000. `--seed` accepts unsigned 32-bit decimal integers. Actions happen before the indicated simulation step and can only change the named valve's boolean state. `--valve gate=on` is a step-zero action. A dry scene rejects valve actions. Exit codes: 0 valid run, 2 invalid request or construction failure, 3 final constraint failure.

## What runs natively

- Deterministic 3D triangle arrays: boxes, a faceted hanging rock underside, and seeded grass placements. Mesh coordinates are local to each geometry object's `position`.
- Fixed 120 Hz gravity and wind integration; axis-separated static AABB collision; bounded dynamic contact projection; inelastic normal contacts and static-support tangential damping.
- Three finite-volume reservoirs with hydraulic-head-driven exchange. Each transfer is bounded by source volume, destination capacity, and equal-head equilibrium, and is subtracted from one reservoir and added to the other.
- A valve puzzle: `feed` starts open, `gate` starts closed. Opening `gate` raises the goal reservoir to the target depth of one unit. `puzzle_solved` reflects that threshold.
- Constraint checks for unique geometry IDs, positive finite bounds, finite triangle data and valid indices, bounded bridge spans, finite body state, penetration tolerance, reservoir capacities, water bounds, conservation, and repair budget.

Actual verification results and measured example invariants are recorded in [docs/status.json](docs/status.json). Tests check reproducibility, grammar/action rejection, deterministic bounded repair, contact at every step of a crowded scene, fixed-step acceleration, resting height, friction, capacity limits, long-run water conservation, isolation when valves are closed, scheduled actions, and JSON mesh/index integrity. The sanitizer target uses AddressSanitizer and UndefinedBehaviorSanitizer. LeakSanitizer is disabled because this execution environment prevents its process/thread inspection; no leak-test pass is claimed.

## Scope and limits

This is an executable first prototype with a renderer-friendly export, not a general game engine. Bodies are translational AABBs with equal masses; there is no rotation, angular momentum, deformable geometry, continuous collision detection, player controller, navmesh, or full rigid-body solver. The bounded procedural scenes keep per-step travel small enough for the tested contact cases. The catch floor is finite (80 × 80); bodies driven beyond it can fall out of the scene. Reservoir water is a lumped conservative volume model, not a spatial fluid simulation; pipes are visual meshes and head differences drive exchange. Generated grass and the rock underside are visual detail, while collision uses explicitly marked static AABBs. The grammar covers the listed scene controls and rejects arbitrary prose. WebAssembly and graphical-native builds are not implemented or claimed.

Portfolio description: **A deterministic C++17 world-generation sandbox that turns a bounded scene grammar into 3D triangle geometry, simulates gravity and AABB contacts at 120 Hz, and solves a conservative reservoir-valve puzzle with validated, reproducible JSON replay.**
