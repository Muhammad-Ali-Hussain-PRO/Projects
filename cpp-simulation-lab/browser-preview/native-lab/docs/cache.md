# VectorGate Cache

**Status: In progress.**

A bounded in-process cosine cache that requires exact metadata isolation before similarity lookup.

## Implemented

- Normalized cosine lookup and exact request hits
- Exact tenant, authorization and model-context namespace isolation
- Entry-count capacity, LRU eviction, expiry and key replacement
- Tested cache core plus a documented proxy adapter boundary

## Reference behavior

Lookup filters by all namespace fields before examining cosine similarity: tenant, authorization scope, model, model revision, system digest, tools digest, decoding digest, knowledge revision and embedding revision. Empty namespace fields are rejected. Request strings are exact cache keys within that namespace; other requests need the configured cosine threshold.

The entry list tracks most-recently-used items at the front, promotes hits, replaces duplicate exact keys and evicts from the back at capacity. Expired entries are removed using a caller-supplied timestamp. Tests cover every metadata field independently, cosine scaling, misses, replacement, expiry, LRU behavior and invalid embeddings.

[PROXY_BOUNDARY.md](PROXY_BOUNDARY.md) specifies authentication, eligibility, canonicalization, provider calls and privacy boundaries that an adapter must implement. The cache does not compute embeddings, authenticate users or establish response equivalence.

## Not yet implemented

- Build an authenticated provider-compatible network adapter
- Add concurrency, byte quotas, invalidation and telemetry
- Calibrate semantic hit quality on domain-specific held-out requests

Single-threaded in-memory cache; not a deployed network proxy. Similarity is not proof of equivalence, and capacity bounds entry count rather than total bytes.

## Build and verify

Run from this directory with a C++17 compiler and Make:

```sh
make test
cat verification.json
```

The tests currently pass 24 checks. The report is generated by the executable, and a failed check makes the command fail. The shared helper is `../test_support.hpp`; keep the research directory structure when copying the project. Build flags include `-Wall -Wextra -Werror`.

## Primary sources

- [GPTCache official documentation](https://gptcache.readthedocs.io/en/stable/usage.html): embedding, similarity evaluation, storage and eviction interfaces.
- [RFC 9111 — HTTP Caching](https://www.rfc-editor.org/rfc/rfc9111): requirements to consider when implementing the future HTTP adapter. The current cache is not an HTTP cache implementation.
